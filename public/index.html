SUPPORT

Pusat
bantuan.

Hal yang paling sering ditanyakan sebelum orang menekan tombol unduh.

Apakah perlu akun atau login?

Tidak. Semua endpoint publik. Link yang butuh login (misalnya Instagram pribadi) memang tidak akan bisa diambil — itu batasan dari platformnya, bukan dari aplikasi ini.

Kenapa satu link gagal padahal sebelumnya bisa?

Platform mengubah struktur halaman hampir tiap minggu. Engine dan provider diperbarui otomatis, dan setiap platform punya beberapa jalur cadangan. Coba lagi beberapa saat, atau tempel ulang link langsung dari tombol Share.

Apakah file disimpan di server?

Tidak permanen. Media dialirkan langsung (streaming) ke browser. Hanya file sementara untuk merge video+audio yang ditulis ke disk, lalu dihapus.

Aman tidak memasukkan token GitHub?

Token hanya dipakai di tab kamu untuk memanggil api.github.com langsung. Server ini tidak pernah menerima, menyimpan, atau mencatatnya. Detail lengkap ada di Docs → Model keamanan.

Boleh dipakai untuk konten apa saja?

Untuk konten yang kamu punya haknya, atau yang lisensinya mengizinkan. Hormati hak cipta dan ketentuan tiap platform.

LANGKAH 1

Hubungkan token GitHub.

Buat fine-grained token dengan akses Contents: Read & write ke repository yang kamu pilih. Token sebesar ini cukup untuk push, dan tidak bisa menyentuh repo lain.

  1. 1 Buka GitHub → Fine-grained tokens
  2. 2 Repository access → All repositories (wajib kalau ingin membuat repo baru)
  3. 3 Permissions → Contents: Read and write, lalu Administration: Read and write untuk membuat/menghapus repo
  4. 4 Hanya mengirim ke repo yang sudah ada? Cukup Contents, dan pilih repo itu saja — token jadi lebih sempit

Token classic (ghp_…) juga bekerja dengan scope repo, tapi cakupannya lebih luas. Fine-grained lebih aman.

Model keamanan

  • Token tidak pernah ke server. Push memanggil api.github.com langsung dari browser; server tidak punya endpoint yang menerima token.
  • Penyimpanan default: memori. Pilihan “ingat di tab ini” memakai sessionStorage yang hilang saat tab ditutup — bukan localStorage.
  • CSP ketat. script-src 'self', tanpa CDN, tanpa inline script. connect-src dibatasi ke origin sendiri + GitHub.
  • Anti-SSRF dua lapis. Allowlist domain CDN, lalu resolusi DNS diperiksa agar tidak mengarah ke alamat privat.
  • Rate limit per IP pada resolve, download, dan seluruh API.
  • Tanpa cookie & tanpa analitik. Tidak ada yang bisa dicuri lewat XSS lintas sesi.

Deploy di Railway

  1. Push folder ini ke GitHub.
  2. Railway → New Project → Deploy from GitHub repo.
  3. Railway membaca railway.json + Dockerfile (yt-dlp & ffmpeg sudah termasuk).
  4. Set NODE_ENV=production dan, bila perlu, YTDLP_COOKIES.
  5. Health check otomatis ke /api/health.
